# The eight stages

Generated by `scripts/gen_catalog_doc.py` from the component and benchmark
registries. Do not edit by hand: run the script.

A RAG pipeline in Lasagna is eight stages behind typed contracts. A component
fills one stage, and the stages around it cannot tell which one is there. That
is what lets a sweep change one stage and hold the rest fixed.

```text
ingest, chunk, embed, retrieve, enhance the query, rerank, agentic loop, generate
```

| Stage | Runs at | Swap it to change | Built in | Sweep key |
|---|---|---|--:|---|
| [Document processor](#document-processor) | ingest | how files are parsed into text | [4](components.md#document-processor) | `config_overrides` |
| [Chunker](#chunker) | ingest | how documents are split | [9](components.md#chunker) | `chunkers:` |
| [Embedder](#embedder) | query time | what vectors are stored | [6](components.md#embedder) | `embedders:` |
| [Retriever](#retriever) | query time | how candidates are fetched | [5](components.md#retriever) | `config_overrides` |
| [Query enhancer](#query-enhancer) | query time | how the query is rewritten before retrieval | [8](components.md#query-enhancer) | `query_enhancers:` |
| [Reranker](#reranker) | query time | the ordering of retrieved candidates | [10](components.md#reranker) | `rerankers:` |
| [Agentic pipeline](#agentic-pipeline) | query time | the multi-step retrieval loop | [7](components.md#agentic-pipeline) | `config_overrides` |
| [Generator](#generator) | answer time | how the answer is written from the retrieved passages | [6](components.md#generator) | `generators:` |

Every stage can be named in a `config_overrides` entry with its stage name, for
example `{name: ircot, agentic_pipeline: ircot}`. Five stages also have a list key
that sweeps several components at once. A document processor does not sweep:
benchmark corpora are loaded as text, so check a processor on your own files.

Registering a component is one decorator. See [Write a component](../guides/write-a-component.md).

## Document processor

Abstract base class for document processors/extractors.

Base class: `BaseDocumentProcessor` in `lasagna.core.base_components`. It runs at ingest. Swap it to change how files are parsed into text.

```python
def extract(file_path: str, **kwargs) -> ProcessedDocument
```

Function form with `@lasagna.document_processor`: `f(file_path) -> str`.

The 4 built-in components are listed in the [component catalog](components.md#document-processor).
